# Platform assistant and project workspaces

The Console's assistant is a second author beside a customer's coding agent, scoped to the Data Workshop. MCP stays the primary surface; both reach the same domain services.

## Turn

- A dataset has at most one `AssistantThread` (`dataset.assistant_thread`) and its append-only `AssistantEvent` log (`user`, `assistant`, `tool_result`, `status`, `summary`). The log is the model context and the transcript. Messages wait in `AssistantInput` until a turn delivers them.
- A turn is one Celery task (`tasks/assistant.run_turn`, queue `assistant`): from the delivered messages to a reply without tool calls, or to a `present` that asks a Question or Choices. `turn.wake` sends it after the commit that queued a message; a second task finds the thread taken and ends. The task starts the next turn itself when messages arrived while it ran.
- A turn takes the thread by raising `AssistantThread.turn` and writes only while it still holds that number (`log.append(..., turn=)` raises `LostTurnError`). `updated_at` is its progress mark. `turn.settle`, called by every read of the thread and every message, marks a turn without progress for `STALE` (15 minutes) as interrupted; no process watches for it. A turn ends itself after `TURN_SECONDS`. An interrupted turn is never resumed: the next message starts a new one, and a call left without a result is answered as abandoned.
- A message for a dataset whose source still lands waits: `_begin` leaves it queued, and the landing task calls `turn.wake_dataset` when it ends.
- A message is delivered with `threads.brief`: what the dataset holds now (source and versions with their `data/<cell>.parquet` path, columns, measured profile, its pipeline). It is attached again only when it changed or a summary replaced the message that carried it.
- When a reply's prompt passes `ASSISTANT_COMPACT_TOKENS`, the turn appends a `summary` of all but the last `COMPACT_KEEP` events. A model call reads the newest summary and the events after it; the transcript keeps everything. The cut never separates a tool call from its result.
- Stop sets `stop_requested`, drops queued messages and stops the conversation's kernel at once (`tasks/assistant.stop_kernel`), so a cell that runs answers. The turn sees the flag at its next step. Jobs the turn started continue.
- The sender of the newest message pays for the model calls (`BillingService.DATA_WORKSHOP`, idempotency key `assistant:<thread>:<sequence>`), and tools run with that sender's project access, checked before each model call. A reply and its charge are saved in one transaction. A reply stopped in the middle is not charged: the provider reports no usage for it.

## Tools

- Catalog tools (`tools.CATALOG_TOOLS`) are MCP tools called in process through `CATALOG.invoke`; validation and receipts are the catalog's own. The turn supplies `project_id`, and `request_key` on mutating tools. A tool that starts a job waits for it in the same call (`tools._wait`).
- Own tools: `run_python` runs a cell in the conversation's kernel; `versions` names the dataset versions it reads, copied into the workspace first. `run_pipeline` retains a package from the model's files, then saves, validates and runs it through the catalog and waits for the run; a `pipeline` argument names either id of a saved pipeline. `present` shows a result.
- Every tool schema starts with a `summary` argument (`tools.SUMMARY`): a few words for the reader. The Console shows it in place of the tool's name, while the call is written and afterwards.
- Publication has one path: a retained pipeline package run by the pipeline runner. The kernel is for exploration only. The assistant has no path to the customer's repository or machine.
- `present` documents are validated by `services/assistant/presentation.py` and stored in `AssistantEvent.presentation`. Charts, tables and metrics read tables the kernel wrote, and an Image is a PNG, JPEG or WebP file it wrote, retained under `MEDIA_ROOT/assistant/<thread>/` by content name. A Question or Choices answer is `{"call", "id", "values"}`.
- `prompt.RULES` sets the conversation: text is for findings, assumptions and answers; data preparation takes the least-changing reading without asking; a question is for a request the data cannot serve.

## Workspaces

- `services/workspaces/` is one contract: `put_data`, `has_data`, `run`, `read_file`, `stop`, `forget`, `remove`. A provider is one module and one entry in `PROVIDERS`; `WORKSPACE_PROVIDER` selects it, and `provider()` refuses an unknown name. Production uses `daytona`; `native` is for local and self-hosted installs with one sandbox server; `nitro` is for AWS on-prem installs. `native` and `nitro` are the same HTTP client (`server.ServerProvider`) for the `/v1/workspaces` API: `native` calls `SANDBOX_URL`, and `nitro` calls `NITRO_SANDBOX_URL`, a server on an EC2 parent that runs AWS Nitro Sandboxes. Settings refuse to start with `nitro` unless `NITRO_SANDBOX_URL` and `NITRO_SANDBOX_TOKEN` are set.
- A project has one workspace. Its `data/` holds each dataset version once, as `<cell>.parquet`, read-only to cells. A conversation has its own kernel and working folder with a `data` link. Variables live in the kernel; files live in the folder.
- Every provider runs `sandbox/kernel.py:run` around a cell: output bounded at 60k characters, the last expression's value, the traceback. A cell runs `DEFAULT_SECONDS` (120) and at most `MAX_SECONDS` (600). A kernel idle for 15 minutes stops; the next cell starts a new one, and `Execution.restarted` tells the model that variables are gone and files remain.
- `native` runs the workspaces in the `sandbox` service (`sandbox/workspaces.py`) on the `workspaces` volume, under the uid and memory admission of a pipeline run, from the same memory budget. Copies are removed oldest first above `DATA_BUDGET_BYTES` (20 GiB).
- Native kernels, pipeline package runs and document extraction share one container and one Linux kernel. A uid keeps a run out of another's files, and `kernel.py:confine` closes the rest without any privilege (Fargate cannot grant `CAP_SYS_ADMIN`): Landlock limits the process and its children to its own folders, the libraries and its own `/proc` entry, denies TCP and scopes signals and abstract sockets; a seccomp filter refuses every socket family but `AF_UNIX`. Landlock applies as far as the host's Linux supports it (files 5.13, TCP 6.7, scoping 6.12); `/health` reports its version as `landlock`. A library that cannot reach a file it needs may abort the process instead of raising, so `conformance.LIBRARY_USE` uses every pinned library; a new library or allowed path is checked there.
- `daytona` gives each project one network-blocked sandbox (2 vCPU, 4 GiB, 5 GiB disk) from the snapshot `manage.py build_workspace_snapshot` builds; the snapshot name hashes the kernel and the image recipe, so a release that changes either needs a build first. A conversation is a code-interpreter context whose working folder is under `/workspace`; `confine` runs inside each context. Sandboxes stop after 15 idle minutes, archive after 60 and are deleted after 7 days stopped. Only `put_data` and `run` create a sandbox; reads, `forget` and `stop` never do. A sandbox keeps the snapshot it was created from, with that release's kernel, for up to 7 days unused: a change to how the server calls the kernel (`SETUP`, `_cell`) must still work with the previous one. A version is uploaded under a temporary name and renamed when whole, `read_file` reads a no-follow copy of a regular file, and `forget` and `remove` raise until the files are gone, so their tasks retry. Tier 1 counts the memory of running sandboxes (10 GiB) and the disk of sandboxes not archived (30 GiB).
- A deleted dataset's copies and conversations leave the workspace (`tasks/assistant.forget_workspace_data`), and a deleted project's workspace goes with it (`remove_workspace`); both retry, because a hosted provider holds customer data.
- `conformance.py` holds the contract checks. The test suite runs them on `native`; `manage.py check_workspaces` runs them on the configured provider, the only way to check a hosted one. `.github/workflows/workspaces.yml` runs it on Daytona each day and on a change to the adapter, the kernel or `uv.lock`; it needs the repository secret `DAYTONA_API_KEY`.

## Live updates

The dataset page holds one stream, `GET /api/datasets/{id}/events/`. It carries signals only: `connected` with the dataset's `updated_at`, the `land_*` progress of its source, `dataset_changed`, `assistant` (the conversation changed: read `GET /api/assistant-threads/{id}/events/?after=N`) and `assistant.draft` (text a reply gained after position `at`, and the summaries of the calls being written). Postgres is the record; the draft key in Redis holds the reply so far for a page that opens in the middle. Members share one conversation: the thread names its `participants`, and the Console labels a teammate's message with it. `log.append` stores what jsonb refuses (a NUL character, a number that is not finite) as a replacement character and null.
