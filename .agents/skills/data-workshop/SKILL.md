# Data Workshop

The native Workshop agent and external coding agents perform interpretation, code and semantic work. Native tasks run the entire Pydantic AI loop in one persistent project-scoped Daytona workspace. Source bytes, references, scripts, notes, a persistent IPython kernel and clean replay are local to that workspace. Temporal supervises the whole run; the backend relays model requests and publishes retained replay artifacts through shared dataset services. Native execution uses no MCP, browser, runtime package installation or per-tool remote transformation service.

`workshop_runtime/agent.py` owns the conversation and local tools: Python, files, clean replay, publication and completion. `session.py` deduplicates Python execution IDs and retains outputs outside the unprivileged kernel user. `replay.py` runs retained packages under a separate UID and filesystem isolation with declared inputs; it shares package validation, provenance inheritance and partition algorithms with publication. The backend independently verifies output hashes, input identity, consumer structure and partition contamination before committing. Successful execution establishes compatibility, not semantic suitability. `row_values.py` shares table-column inference with the store: replay materializes absent fields as null and promotes mixed integer/float columns only when precision is safe. Load staged Parquet with `workshop_runtime.data.read_frame` to preserve nullable integers and decode platform JSON columns. Parent declarations are consumed at each step; successors receive assigned `source_row` identities. Replay scripts receive ordinary data columns and `source_row`; managed `_overmind_` metadata is omitted except explicit parent declarations. Source metadata needed by a recipe must be retained explicitly as ordinary evidence-bound data. Omit a partition recipe for an unsplit output; supplied recipes require two to four positive role fractions.

## Preparation lifecycle

The first native request in any project reserves a workspace; the Temporal worker provisions it from the deployment-wide `WORKSHOP_RUNTIME_SNAPSHOT` before execution. API and worker share that snapshot name. Reads never allocate resources. PostgreSQL retains creation intent and project/runtime labels; unknown acknowledgements reconcile without resubmission. Definite setup rejection ends the task and its preparation so an explicit retry can proceed. Disabled bindings remain disabled. Qualified workspaces stay running for subsequent tasks. Existing workspace upgrades still require the checkpointed operator command.

Before reasoning, `workshop_agent/workspace.py` checks the immutable runtime, pins the source cell, checksum-verifies Parquet and retained originals, and stages task/context files, workflow guidance, project context and consumer contracts. `transfer.py` uploads gzip bytes once, verifies the SHA-256 and exact expanded length inside Daytona, then atomically installs read-only input. A retry rehashes an existing destination before reusing it. Failed verification preserves the previous file. Staging and publication retain measured phase timings outside the model context. Optional `context_datasets` on native task start are project-validated, frozen to exact published cells, and retained in `WorkshopTask.context_sources`. Bootstrap checksum-verifies and stages their Parquet and original bytes under `data/context-datasets/`, listed in `input.json`. These are separate read-only references; publication still targets the working dataset. Recipes using reference values retain the needed values and attribution in their package for clean replay. Synthetic taxonomy examples are checked by the installed training/evaluation readers. No external reference webpage is needed. User intent remains open-ended; the agent derives target meaning, assumptions, field roles, transformations and checks from evidence. The generic workflow calls for orientation before transformation and independent verification afterwards; there are no model-authored plan objects masquerading as semantic validation.

`workshop_agent/resident.py` claims one workspace owner, reattaches after coordinator loss, and retains model responses before delivering them. Exchanges run through the standard-library-only `workshop_runtime/mailbox.py`, with a bounded local wait and no fixed sleep while running; model and data libraries load only in the resident runner. The supervisor retains one validated Daytona transport and checks the live owner/sandbox/generation on each exchange; recovery revalidates attachment. Bootstrap reference files transfer in batches with complete path/byte verification. Publication transfers replay packages, outputs and assignments in one compressed archive, verifying the archive and members before retaining every original artifact hash and lineage check. Model calls use OpenRouter's streaming Responses endpoint through a reused HTTP client (`OPENROUTER_API_KEY` stays in the backend). Requests carry full retained context, including provider metadata. The initial context includes the pinned replay contract and local Agent Skills catalog in a stable prefix. Decision and conversation skills load alongside an exploratory Python call, returning only the relevant native consumer contracts; full taxonomy and contracts remain local read-only files. The first request also includes the pinned input manifest, measured source context and platform briefing after the stable prefix. Initial context omits duplicate profiles, consumer contracts and examples, identifying the complete local files instead. A checksum-verified briefing measures all source rows, observed types, nulls, blanks and exact duplicates. Its backend-owned cache is bound to project, dataset, cell, source SHA, runtime and profiler version; the agent still assesses semantic suitability and leakage. Native references name the precision-preserving reader, normalized record conversion, saved receipt envelope and exact canonical-fingerprint assertion; similarity guidance covers distance, missingness, threshold boundaries and applicable normalization views before packaging. Matching views are reconciled transitively; independent checks preserve accepted relationships across optimizations rather than equating larger edge counts with coverage. Related read-only inspections and their notes share one Python call. Full-population checks precompute source/group lookups and pairwise masks; large comparisons use bounded blocks or indexes. Independent validation uses the same explicit numeric boundary convention, never fewer checks to improve timing. Tool observations retain valid JSON, bounded previews and explicit omissions with complete local receipts; explicit paginated reads preserve requested contents. data.stage and replay share the same input projection, excluding platform-managed metadata. Markdown notes are accepted in packages; the native contract documents package preflight and nullable column semantics. The conversation skill explicitly distinguishes local column/schema checks from the full chat validator, which runs during platform publication before acceptance; the minimal Daytona image does not expose that reader. Source/message/role checks remain independent and local. The agent assesses missingness and split grouping before authoring the package and checks actual transformed values before publication. The publisher verifies output counts, split counts and assignment digests against retained replay, returning `verified_against_replay` so the agent can conclude directly without another receipt-reading call or duplicate handoff tables. This verifies publication fidelity, not semantic suitability. Requested visual analysis retains the presentation tool. An uncertain model acknowledgement is not automatically resubmitted. A clarification-blocked task releases its workspace slot only after a successful finish event, observed runner exit, no pending requests and no uncertain actions. Its task and files remain retained; an unreconciled stop keeps ownership. Protected replay receipts are the publication authority; workspace generation and runtime are pinned to the task. Conversation checkpoints and verified settled-task file snapshots are retained in platform storage. `workshop_agent/cache.py` runs idle-project retention and LRU eviction in the existing native worker: `WORKSHOP_CACHE_BYTES` defaults to 2 GiB of inactive verified copies. Active, paused, uncertain, unretained and unknown files stay pinned. `cache_files.py` verifies inventories and bounded chunks; restoration verifies a staging directory before atomic installation. Live kernel memory and active changes since the last retained snapshot are not protected against total disk loss. Source/context files are read-only to the kernel. Tasks have no token budget; `max_steps=0` means no action-count limit. Provider usage stays unknown when not reported.

Native completion retains primary dataset cells and completed partition members in the task result. The preparation record stores only its own primary cells. Project-scoped pause, resume and cancellation control the resident supervisor. Console cancellation revokes publication authority. Runtime processes and data stay together; external training/evaluation/inference launches remain outside this agent's authority.

`DatasetPreparation` (`services/datasets/preparation_workflow.py`) groups a coding agent's preparation work under one evolving notification. External agents use MCP `start_dataset_preparation` and `update_dataset_preparation`. Native tasks own their preparation lifecycle; Console Transform data and MCP `start_workshop_task` start the same task service. Pause, resume and cancellation are project-scoped; uncertain remote actions fence workspace reuse. The end-preparation API (`POST /api/datasets/{id}/end-preparation/`) and the dataset reaper (24 h without activity) cancel it. The Console exposes native task controls in the chat bar, without a separate preparation banner. An open preparation labels the dataset; it never locks editing.

## Sources and landing

- A dataset may start from a written `brief` with no source or capability. Purpose is explicit (`train`, `eval`, `explore`) and otherwise stays pending; when no capability is given, REST and MCP landing assign the top-ranked capability if its score is above zero; CLI transfers never infer one.
- The first source attaches to the draft; later uploads append versions. Original bytes, extraction metadata and row evidence are retained.
- CLI uploads use `DatasetTransfer`: a project request key binds SHA-256, byte count and destination. Up to 100 ordered files and 2 GiB per transfer; file order is part of identity; one batch becomes one source cell or one version. Repeat the identical command after an interruption. `get_job(kind=dataset_transfer)` reads byte and publication state; `dataset_run` reports landing. An explicit `--json-rows-field` selects a top-level JSON row array and is recorded.
- Local upload, export and checkpoint download authenticate separately from MCP. Without an explicit or repository key they use the address-bound account connection at `$XDG_CONFIG_HOME/overmind/connection.toml` (mode `0600`); repository keys are endpoint-bound too. `overmind connection check --project-id PROJECT --json` verifies MCP and transfer access from the invoking environment; MCP connectivity alone is not readiness. Verify the installed CLI from the workspace and from a repository-free directory.
- Confirmed permission denial uses the host's scoped approval. Missing credentials and transfer errors never authorize a browser fallback or an automatic sandbox-policy change.
- Landing admission is one import per project, least-recent-project first, up to the observed landing capacity (backend-architecture `references/celery.md`). A lost started import needs explicit `resume_dataset_import`.
- Trace sources pin `preferred_capability_id`. A unique matching invocation scopes I/O, transcript, usage and score; repeated invocations fail before publication; unmatched traces keep whole-trace evidence. Missing wrapper I/O stays missing and never borrows tool arguments.

## Documents and OCR

- Parsing runs in the `sandbox` service without app credentials, media mounts or outbound network. Landing streams bytes and progress; missing parser configuration fails closed; there is no in-process fallback.
- PDF pages the primary parser misses are recovered through PDFium before OCR. `native_text_recovery` records engine, pages and counts; encoding artifacts are flagged, never corrected.
- OCR is local Tesseract, English by default, with explicit languages through `update_dataset(ocr_languages=[...])` on a draft before upload. Completed pages are cached per project for 30 days, keyed by document, language policy, engine and parser settings.
- Limits (100 MiB per document, 2,000 PDF pages) are discoverable at `overmind://dataset-upload` and enforced before extraction.

## Pipelines

- New revisions need a retained Python package with agent-authored stages; inline operations are rejected (`pipeline_package_required`). Package-free historical revisions are read-only.
- Revisions are immutable and numbered per project family; `derived_from` starts a separate attributed family. Revision keys are project-scoped; run keys are per dataset.
- Packages run only in the isolated sandbox through interactive workers: separate UIDs, no network, credentials, media mounts or Docker socket, measured memory admission. Registration and validation never execute code. Process exit status, not a script-written file, establishes completion.
- Steps declare `id` and `input`; `inputs` concatenates disjoint earlier branches in order and rejects overlapping `source_row` identities. It is not a relational join. `flow` (`pipeline_graph.py`) returns `nodes`, `edges` (each with its `condition`), `terminal_steps` and `unconsumed_steps`. Script conditions cite `expression` and `line` and never execute as expressions.
- A successful run publishes all step cells atomically. Preview publishes nothing. `min_rows`/`max_rows` apply at publication and show as deferred in previews; row preservation, schema and lineage checks apply in both. Run receipts expose queue age, a polling interval, terminal time and structured failed checks. Runner heartbeats continue through validation and publication without advancing measured progress.
- Cells carry receipt-backed `transformation` attribution (run, revision, package checksum, entrypoint). External imports and unrecorded history never claim platform execution. Every retained package file is inspectable with checksum-verified pagination.
- Recovery is lease expiry: the `reap_stuck_runs` beat task calls `workbench.expire_runs`, which fails runs past their lease without publishing partial output or replaying scripts.
- Failure or cancellation leaves source and consumer versions unchanged. Cancellation prevents publication; it does not claim to stop a running calculation.
- `batch_rows` (1–100,000) splits a row-independent step into separate sandbox runs (`pipeline_execution.py`); global sorting, grouping, splitting and deduplication must not batch.
- Bindings start paused, pin a revision, and rebuild full source snapshots; checkpoint and cells commit together.
- Keep each step's logic in its visible entrypoint; helpers hold reusable utilities, not an opaque dispatcher. Change a recipe through a new revision and run; never rewrite historical scripts.
- `save_dataset_pipeline(dataset=..., package=...)` associates the script with the dataset's preparation; retrying an older request never resets a newer association.
- Corrections update the same family and run against the original source; the clean process replaces the displayed cells. There is no repair history or restore view.

## External imports

External results arrive inline (at most 2,000 rows or 4 MiB) or as a project-scoped artifact cell. Every row keeps `source_row` or declares all parents in `_overmind_parent_rows`; publication validates every parent (`review.py`, `workbench.py`). External runs are recorded as `external_attributed`, and their cells' `transformation.execution` is `external_import`. Never promote source references or supplied review flags into proof of semantic correctness.

## Storage and queries

- XLSX landing streams all worksheets through `spreadsheets.py`, using first-row headers. `_overmind_spreadsheet` retains worksheet/row and formula, error or date types. Formulas stay text, dates use ISO strings, and original bytes remain available. Ambiguous headers and rows wider than the header are refused; no formula evaluation occurs. XLSX is capped at 100 MiB compressed and 512 MiB expanded.
- Frames are Parquet at `MEDIA_ROOT/datasets/<dataset>/cells/<cell>.parquet`. Cell IDs bind versions; version labels are derived. Source identity is `source_row`, not display position.
- A column becomes JSON when it mixes kinds, holds an integer outside signed 64-bit range, or mixes floats with an integer a float cannot represent exactly (`store.py`). Shared pandas readers must not coerce these values again.
- `query_dataset` caps output at 100 rows and 32 KiB and returns `query_result_too_large` without clipping; a configurable ten-second deadline returns `query_timeout`. Redis admission bounds MCP SQL globally and per project; busy admission returns a retryable error with the cell and retry delay.
- `overmind dataset export --source SHA256` downloads retained originals with byte verification.

## Checks and consumers

- The platform measures format and change impact. Semantic quality stays unmeasured without attributable evidence; technical compatibility is not semantic correctness. Do not add a universal quality gate.
- Preserve probability targets, option order, weights, duplicates, blank states and declared groups. Never argmax soft targets or invent distributions from means. Decision recipes publish a typed `decision` with tied maxima and supervision metadata.
- The native agent declares target meaning per family from evidence in retained code and output metadata; unknown meaning stays unknown. Historical preparation plans are not a writable API. Profiles and impact checks keep declared supervision metadata, so a changed weight or semantic declaration shows in review.
- Publication measures analytics on the full rows, bound to the exact fingerprint and rule version. They are advisory; `explore_dataset` backfills older cells, and reads never scan.
- Raw tables have no inferred feature or target mapping; column names such as `label` or `score` never select columns.
- Column contracts use `object` for a nested decision. A final step's `consumer` (`decision_train`, `decision_eval`, `chat_train`, `model_eval`) validates targets in preview and publication.
- `use.check` verifies technical fit; `use.use` and `use.freeze` pin exact cells inside the consumer transaction.
- The native agent inspects the named capability and verifies published output before it calls preparation complete. Format readiness does not establish task suitability.

## Console canvas

Inventory checkboxes attach existing datasets as removable composer chips; selection survives filtering and pagination. Without uploads, the first selection is the working dataset. With uploads, Send creates the working source and waits for landing. Remaining selections are read-only context datasets. Send requires an objective and at least one ready attachment, then submits one request-keyed native task and opens its workspace. Failed agent submissions retry with the same key. Accepted submissions carry the composer into the workspace as a single-line bottom bar using a shared-element view transition. Hover, keyboard focus or a tap expands it; Escape collapses it without clearing the draft. The collapsed bar shows the current recorded action. Hover reveals only the composer and compact controls; availability appears in the Send tooltip. The expand icon opens the full floating left conversation, and the bottom minimize control tucks it away without clearing the draft. Sending a follow-up also opens the conversation. Queued messages stack directly above the input in the same width-constrained composer group; they also appear when the dock is expanded. The Console exposes Stop, not Pause/Resume. Only the outer panel fills the workspace height; history scrolls above the separately bordered, compact input. The right edge resizes the panel by pointer or keyboard within the available workspace; width survives closing and reopening. The transcript follows the approved Hex references: 14px reading text, 12px metadata, content-width prompts aligned right, unboxed replies, quiet text disclosures and inline cell links. Prompt bubbles and the compact composer use the standard small radii, a quiet prompt marker and crisp neutral borders. Tool-group counts use compact uppercase tracking, while prose keeps normal casing and reading size. The terminal character comes from geometry and typography, without scanlines, glow or ornamental telemetry. A pointer-transparent blur and fade softens both edges of the headerless history above the composer; scroll-end padding keeps the final message readable. Consecutive same-task tool calls use assistant-ui native tool-call parts and borderless ToolGroup/ToolFallback components with recorded summaries, visible tool names, inputs and errors; active or failed groups open by default. Provider tool-call fragments emit preparing activity before execution, sharing the resident action ID so execution updates the same row. Public text and input fragments flush independently. Partial inputs are display-only; private provider reasoning is never projected. Interrupted streams and terminal snapshots settle unexecuted preparation rows. Markdown tables use horizontal rules without card frames; code uses the Console wash tokens. One assistant-ui runtime wraps the Workshop panel and composer. Composer primitives own drafts, Enter/Shift+Enter, Send and Stop; its external queue adapter maps durable server messages and revision-checked controls. Queue primitives render pending messages; Workshop retains its edit and reorder controls. Landing also uses the native composer with the existing resumable uploader. Failed sends restore untouched drafts, and failed landing retains its objective. Native action-bar copy and scroll-to-latest controls accompany the transcript. Streamdown formats streamed public text, and exact cell references focus the canvas. Selected cells accompany the next message. Project-scoped request keys deduplicate sends. A durable PostgreSQL event cursor replays messages after browser reconnect; provider reasoning stays private. Follow-ups enter the resident loop between actions; messages arriving at a settled finish restart it with retained files and a fresh kernel. New tasks retain prior public conversation. Referenced cell versions are frozen, checksum-staged as read-only Parquet, and delivered with local paths. While running, the icon-only send control adds follow-ups to an editable queue. Compact rows expose Send, Delete and Edit; a handle supports drag or arrow-key reordering. Send prioritizes a message at the next action boundary. Queue order is retained by the backend. Edit/remove/move require the current message revision and a request key; delivery is claimed before writing immutable sandbox inbox files. Stop cancels the run, revokes publication and interrupts native work; pause/resume retain the run. Control delivery proceeds during model streaming. Remote provider compute may finish after local cancellation. Drafts survive Stop, and unread messages become cancelled. The dataset inventory is a foreground panel that slides over the stationary composer. Its notch joins the panel edge, docks under the top bar when expanded and points down to return. Composer state, filters and pagination stay mounted; reduced-motion settings disable the slide and meteor animation.
