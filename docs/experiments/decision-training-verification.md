# Native decision training verification

> Historical experiment record. Current implementation and qualification are tracked in [the platform verification report](platform-improvements/verification-plan.md). Earlier launch holds, runtime limitations and estimates below describe their recorded point in time. The authorized full run is `a356c75d-788a-4a35-bd30-1d24ae7afab8`; its existing completion protocol remains authoritative. New platform changes are isolated and have not been deployed over it.

Failure modes to qualify before a paid full run:

- A soft target is collapsed to argmax, ignored, renormalized silently, or included in the input prompt.
- A malformed target, duplicate option, unknown field, nonfinite weight, or mismatched objective passes the data boundary.
- Two different targets share a preparation cache key; tokenizer/codebook changes reuse stale tokens.
- The option code merges with the decision boundary, or one option requires multiple tokens.
- Padding affects the final decision state, padded classes receive mass, or option permutation fails to preserve identities.
- The model's effective output head is bypassed (LoRA/quantization), or the decoder is detached from gradients.
- Accumulation averages microbatch means rather than weighted decisions; checkpoint reload changes updates.
- A long row is silently truncated, a large corpus is fully materialized, or interrupted publication is accepted.
- A native decision checkpoint is mistakenly evaluated as generated text or advertised as a chat model.
- A final benchmark enters training, calibration, checkpoint selection, or recipe tuning.

The isolated contract checks protect the shared worker/API boundary and exact preparation identities. Numerical checks use a tiny trainable decoder and compare one optimizer update against an unsplit batch, including unequal weights and padding. GPU qualification must then cover the real Qwen/Unsloth decoder, checkpoint reload, before/after probabilities and measured throughput. Full corpus execution is contingent on these observed checks, not on launch authorization (already granted).

Run receipts will record commands, pinned inputs, environment, outputs and limitations here or in the linked experiment artifact.
