## Boundaries already implemented

- Workshop owns evidence-preserving transformation, exclusions and provenance. Native rows carry `decision` plus source/group/license metadata. The same shared lifecycle serves Console, REST and MCP.
- File import, explicit `transform_batch(df)` transformations, proposal review and deterministic audits process bounded batches or disk indexes. Ordinary Python cells retain whole-frame semantics. SQL queries can read only registered Parquet paths, with locked external-access settings and a 512 MB DuckDB budget. Source train/eval splitting still retains its row collection; this experiment uses separate source datasets.
- Training freezes the objective from the selected dataset, renders inputs, verifies each option is one next token, and streams the exact token artifact. Packing and ordinary chat evaluations are incompatible with this native objective. Current native support is one-GPU Modal LoRA.
- The engine reads the final prompt hidden state through the effective output head and applies an option mask. FP32 log-softmax computes the weighted loss; gradients remain connected to the backbone. Saved adapters must reproduce their recorded probability probes in a fresh process before publication.
- Optimizer recovery binds the immutable base identity, data and configuration. CPU qualification verifies AdamW moments, cosine schedule and Python/torch RNG through exact subsequent updates. The GPU interruption experiment restored committed steps 14, 21 and 27, completed its 80-step schedule and passed fresh checkpoint reload. Independent GPU training is not bitwise reproducible.
- Input-only request validation and tokenization separate inference from reference distributions. Supplying gold labels or metadata as request fields is rejected; training and inference inputs share one renderer.
- Verified native checkpoints have a content-addressed `artifact.json`; changed files or failed reload checks prevent publication. Completion is idempotent after final artifact publication. Native jobs permit provider retries and restore the optimizer checkpoint across attempts.
- A dedicated experimental Modal evaluation app performs CPU preparation and GPU probability scoring with the shared family loader. It records input/model identities and full stable log-probabilities. GPU inference reproduced all 64 saved training probes within a maximum absolute probability difference of 1.49e-8. This worker is CLI-guided and has not yet become a platform `EvalRun` mode.
- The benchmark scoring CLI validates sealed inputs/references and prediction identities, retains missing/invalid coverage, and reports full-distribution metrics, grouped bootstrap intervals, reliability, selective reference mass and benchmark slices. Paired comparisons use shared valid decisions and grouped differences; CLINC reports OOS AUROC, average precision and observed FPR at 95% TPR. Fitted calibration and robustness suites remain outstanding.

## Product integration contract

1. **Training setup.** Show “Decision probabilities” as the objective inferred from a compatible selected dataset. LoRA versus full weights remains a separate choice, with only qualified methods offered. Show decisions, source coverage, context compatibility and measured cost basis. Native jobs select native benchmark datasets directly; remove the current artificial requirement to attach a chat evaluator set while disabling every chat evaluation flag.
1. **Model artifacts.** Register a project-scoped decision artifact at successful training completion. Its immutable manifest includes base revision/identity, adapter checksums, stack identity, renderer, tokenizer/template fingerprints, codebook, input contract and objective. Archive it to checkpoint storage and support download without creating a chat deployment. A trained artifact and a live deployment are distinct states.
1. **Evaluation.** Extend the existing evaluation lifecycle with an explicit decision mode and artifact references, rather than disguising probabilities as generated text. Pin dataset cells and baseline/candidate artifacts. Run both through the identical input-only renderer. Persist complete vectors, stable log-probabilities, technical failures, group identities and input hashes. Deterministic metrics require no generative judge. Do not bind these research runs to product evaluator sets.
1. **Metrics and comparison.** Report per-benchmark and macro-across-benchmark accuracy/F1, NLL, full-vector Brier, and RPS for ordered distributions. Mean-only references permit expected-score errors, not invented categorical NLL. Add calibration/reliability and selective-accuracy curves, OOS detection, language/subject/heuristic slices, grouped confidence intervals and paired comparisons. Keep missing or technically invalid predictions visible in coverage. Score option permutations only where wording and ordinal meaning permit them; add equivalent-format and evidence-injection stress cases as separate suites.
1. **Typed inference.** Expose one decision request schema shared by batch benchmarks and interactive serving. Return full probabilities with explicit option identities, model artifact identity and renderer version. Keep state-prefix reuse as a later measured optimization: Qwen3.5's recurrent layers also require independent branch state. Do not route these artifacts through chat-completion workers or silently replace the existing external Jev provider.
1. **Activation.** Qualify latency, memory, concurrency, reload parity and cancellation before making a native worker deployable. Use an explicit decision model selection and the durable activation lifecycle. Benchmark selection remains independent of the model handling live product traffic.
1. **Consistent surfaces.** Add the artifact/evaluation contract in domain services, then REST serializers and MCP tools/resources/prompts, generated OpenAPI types, Console setup/results/playground, and CLI exports. Update capability consumers only when their typed decision interface is supported. Preserve project scoping, billing, idempotent transitions and cancellation. No commit, push or product model activation has been performed in this experiment.
