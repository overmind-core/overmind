# Cross-run engineering lessons

These lessons were distilled from accessible fraud, KYC and chat-smoke histories
plus typed-decision research, Titanic and public benchmark histories. Discovery
covered nine accessible local projects and 26 saved training experiments; prepared
plans are not counted as executed GPU runs. Direct legacy jobs may not appear in
that listing. These are observed patterns, not claims about every deployment. Exact IDs, measurements and audit scope
belong in the accompanying experiment review, not this reusable skill.

| Observed pattern                                                                                                                 | Engineering response                                                                                           | What the evidence does not establish                                                                            |
| -------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------- |
| Technically completed KYC pilots had lower loss but remained below a simple text baseline; important classes had no predictions. | Check declared task metrics, class support/predictions and simple baselines before scaling.                    | That every recipe fails or that the platform caused poor learnability.                                          |
| Case families connected several thread IDs.                                                                                      | Split at the appropriate connected independent unit, not the most convenient ID.                               | That every task needs identical grouping or split fractions.                                                    |
| A completed fraud comparison contained thousands of training-related final rows.                                                 | Audit inherited groups and exact inputs before freezing the holdout; invalidate contaminated quality claims.   | That technical scoring success makes the comparison trustworthy.                                                |
| A generic raw-row fingerprint heuristic treated a geographic state as the whole model input.                                     | Keep raw identity distinct from model-input semantics; fix shared code and rebuild affected immutable lineage. | That arbitrary columns should be renamed or lineage checks disabled.                                            |
| Preparation and launch defaults resolved differently, creating confusing setup records.                                          | Carry identical explicit configuration; reconcile internal rows with provider IDs.                             | That two dashboard rows necessarily mean two GPU jobs.                                                          |
| Provider work succeeded while evidence collection stalled.                                                                       | Separate execution from collection; recover existing receipts before retrying.                                 | That a stalled collector justifies another submission.                                                          |
| Alternate-provider identity checks failed, and other comparisons retained unknown acknowledgements.                              | Qualify exact model identity; report missing counts and preserve uncertainty without blind replay.             | A zero model-quality score for missing outputs.                                                                 |
| A research experiment reported failure although its training child succeeded and the comparison had an unknown submission.       | Inspect each lifecycle stage separately and preserve completed work.                                           | That the trained weights failed or that restarting training repairs a benchmark.                                |
| Repeated feasibility plans were prepared without child jobs.                                                                     | Count provider submissions separately from drafts, preparations and experiments.                               | Duplicate GPU execution or evidence that a model was trained.                                                   |
| Completed Titanic and public benchmark jobs retained reload checks and linked comparisons.                                       | Preserve artifact checks and frozen comparison receipts as positive workflow evidence.                         | That every model improved, that pretraining overlap is absent, or that the last checkpoint is universally best. |
| Very short chat jobs completed hardware execution.                                                                               | Treat them as bounded infrastructure evidence.                                                                 | Generalization, useful training duration, checkpoint parity or production readiness.                            |

## Applying lessons without overfitting the playbook

Use these incidents to choose checks, not to copy their hyperparameters or numerical
quality thresholds. Assign ownership: agents own semantics and experimental design;
platforms own durable identities, faithful preparation and lifecycle reporting;
providers own execution/acknowledgement; some causes remain uncertain until measured.
A skill can improve agent decisions but does not repair platform invariants.

When testing a revised skill, use realistic cases: an imbalanced classification task,
a connected-case dataset, a generative task with correct loss but poor task output,
and an uncertain provider launch. Assess observable choices: protected holdouts,
honest evidence scope, exact launch configuration and no duplicate dispatch.
Frontmatter validation only checks packaging. A live restart tests the workflow,
not a causal claim that the skill improved model accuracy.

General guidance is maintained separately in [practice foundations](foundations.md).
