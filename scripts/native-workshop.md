# Native Data Workshop

Upload data in the Console, open the dataset and choose **Transform data**. Supply an objective such as “I want to train a decision model on this data”. The native agent explores the evidence, writes reusable code, replays it cleanly and publishes verified artifacts. The Console streams public responses and retained actions. Sending a follow-up opens a floating conversation with exact cell references; selected cells are frozen and staged locally before delivery. Follow-ups enter between actions and survive reconnects; private provider reasoning is not exposed. Queue adds follow-ups while running; pending messages can be edited or removed until delivery is claimed. Stop cancels native execution and prevents further publication, while Pause/Resume retain the run. Provider requests already sent may finish remotely. Message revisions and request keys prevent stale edits and duplicate retries. External coding-agent preparation remains available. Training, evaluation and inference launches are outside this agent's authority.

Supervisor exchanges use a standard-library-only mailbox command. It retains responses and inbox messages atomically, rejects conflicting retries, and waits at most one second for the next external request. Running tasks have no fixed supervisor sleep; paused tasks retain a bounded poll. Agent/model imports remain in the long-lived runner. The supervisor reuses one validated Daytona transport while checking the current workspace owner, sandbox and generation before every exchange; a replacement supervisor validates a fresh attachment. The mailbox is included in the immutable runtime identity.

## Runtime boundary

One persistent private Daytona workspace per project contains the Pydantic AI reasoning loop, pinned source files, local platform references, notes, scripts, a persistent IPython kernel and replay execution. Python provides direct access to files, SQL and shell subprocesses. Dependencies and tokenizer assets are installed in the immutable image; runtime package installation and outbound sandbox networking are disabled.

Temporal supervises a whole resident run. The backend supplies external capabilities through a protected mailbox: credentialed model requests, shared-service publication and retained visual responses. It does not select each action or execute transformations elsewhere. The agent uses no MCP, browser or reference webpage. Model credentials never enter the sandbox.

`workspace.prepare` checks the release, pins and verifies source bytes and stages task/context, workflow and consumer contracts before the first model request. Reference files transfer in one batch and every returned path and byte sequence is checked before launch. Publication compresses its package, step outputs and assignments into one temporary archive after reading the trusted replay receipt. The archive checksum and member list are verified, followed by every original artifact hash and reconstructed input; compression changes only transport. The first model request includes the exact pinned input manifest, measured source context and platform briefing after the stable shared contracts. Notes are updated within exploration or authoring calls. Markdown notes are accepted in retained packages; package preflight and nullable-column semantics are documented. Publication checks row counts, split counts and assignment digests against the retained replay and returns `verified_against_replay`; this establishes publication fidelity, not semantic suitability, so the agent still independently checks actual values before publishing. It can conclude directly from that receipt. The agent derives task semantics from user intent and evidence. Generic guidance requires exploration, leakage analysis and independent checks without supplying a dataset-specific recipe or requiring ceremonial plan-tool updates.

## Interactive responses

The resident `present` tool reads a local JSON document, computed JSON tables and PNG/JPEG/WebP plots. `presentation.json` carries the component catalog and examples beside the data. The agent can compose charts, searchable/sortable tables, metrics, source-cell links, text, code, tabs, disclosures, steps, forms and choices. It does not generate executable JSX, arbitrary URLs or client-side data queries. Source references freeze exact published cells and retain their fingerprints; they establish provenance, not semantic correctness.

`frontend/src/components/datasets/workshop-ui-catalog.ts` defines the Zod catalog. Run `bun scripts/workshop-ui-catalog.ts` from `frontend/` after changing it; `check:workshop-ui` verifies the generated runtime schema. The shared Python validator compiles component nodes to OpenUI Lang. OpenUI renders in the existing assistant-ui transcript with Overmind tokens and controls. Prose streams during reasoning; visual responses appear after validation and are replayed from PostgreSQL with their exact data. These files are bounded to 2 MiB and 2,000 rows per data reference; aggregate or explicitly sample larger results. Missing numeric chart values are rejected rather than converted to zeros.

Questions and choices submit `interaction: {message, component, values}` through `send_workshop_message` / the Console messages endpoint. The server checks the original question, project, dataset, allowed values and duplicate answers, then reconstructs the native follow-up. A response can queue or continue a settled task; it never directly invokes training or a transformation. Remove a queued response to answer again; free-text editing of structured responses is rejected. Accepted answers survive reconnects. Unsent form drafts survive closing the panel in the same browser session.

## Local setup

Store `DAYTONA_API_KEY` in a mode-0600 `~/.config/overmind/workshop.env`, outside the repository. Compose loads it for the native worker; `WORKSHOP_AGENT_ENV_FILE` overrides the path. `WORKSHOP_AGENT_MODEL` optionally supplies an OpenRouter model slug instead of the central model registry. Model requests use `OPENROUTER_API_KEY` on the backend through a reused HTTP client and the streaming Responses endpoint. Credentials never enter the Daytona workspace. Every request sends full retained context; provider metadata survives coordinator replacement. A lost in-flight response remains unknown and is never retried automatically.

Source staging uses a one-way gzip upload with SHA-256 and exact expanded-size verification inside Daytona. Only a fully verified temporary file is atomically installed as read-only input. A retry hashes the existing destination and skips transmission only when it still matches; corrupt, truncated or oversized transfers leave the previous input intact. `staging_metrics` records actual compression, upload, verification and reuse timings outside the model context. Publication retains separate transfer, replay-verification, pipeline and partition timings on its immutable run receipt. No consumer, lineage, full-row or partition check is removed.

Matching normalization is part of the quality contract. The native reference asks the agent to compare applicable normalization views, reconcile their relationships before partitioning, and independently verify every adopted view against actual split membership. Optimizations preserve accepted relationships unless source evidence justifies a semantic change; a larger edge count alone does not prove coverage. Exact candidate indexes can reduce verification work without weakening the check.

The initial model context carries the pinned native replay contract and local skill catalog before task-specific input. Relevant consumer contracts load intact with the first exploration result, without a separate model round trip. Full taxonomy, source data and supplementary guidance remain local. Initial context omits duplicate profiles and consumer examples while identifying their complete local files; the verified briefing supplies measured source facts. Native references give the installed data-reader calls, saved receipt envelope and exact canonical-record fingerprint assertion explicitly; byte hashes and record fingerprints are distinct. Split guidance requires data-appropriate distance and missingness checks across bucket boundaries before packaging, with sensitivity to nearby tolerances and the measured similarity definition retained. Related inspections can share a Python call; the agent assesses missingness and grouping before authoring the final package. Publication emits native cell references, so a transformation can conclude after receipt verification without constructing a redundant presentation. Requested visual analysis still uses the presentation tool.

Build a snapshot with `workshop_runtime.image.build_image` and set `WORKSHOP_RUNTIME_SNAPSHOT` to its published name in both the API and worker environment. The first native request in each project reserves a workspace and Temporal provisions it before execution. Reads never allocate resources. Workspaces remain running for reuse; disabled bindings stay disabled. Creation intent, runtime identity and provider labels are retained in PostgreSQL. Lost acknowledgements are reconciled by label without another create request. A definite rejection ends the task and permits an explicit retry after capacity or configuration is repaired. Unconfirmed creation requires reconciliation.

For an existing workspace upgrade, run `provision_workshop_workspace --project UUID --snapshot NAME --state PATH` for an authorised upgrade. The receipt reconciles creation and must be retained outside the repository. Checkpoint verification precedes rebinding; the idle previous workspace is checkpointed and stopped before allocating its replacement, avoiding overlapping memory allocations. Archival releases its disk quota asynchronously; an explicit quota rejection is retained and can be retried after storage becomes available. Its binding stays disabled during the upgrade, and the previous workspace remains retained. Checkpoints are bounded to 2 GiB compressed and 8 GiB expanded; restore checks available disk for both the archive and extracted files before transferring. Never clear an uncertain creation receipt or blindly create another workspace. The workspace must be private, always running, without automatic pause/deletion and with all outbound networking blocked.

The local Compose `workshop-agent` profile starts Temporal and its dedicated worker. Use the existing Compose project name. Rebuild the application image after runtime/dependency changes, then recreate affected workers. The dedicated native worker does not hot-reload: pause active tasks and settle in-flight model calls before restarting it. Production needs a durable Temporal deployment; the Compose development server is not a production topology.

## Execution and recovery

The resident runner retains conversation state and full receipts outside the unprivileged kernel. Each Python execution has a stable ID. Restarting the runner reattaches to a still-live kernel execution instead of repeating its effects. Losing the kernel namespace is distinct from losing the runner and requires recovery from retained code/files. Source and context are read-only.

Clean replay uses a separate UID and filesystem isolation. It sees declared package inputs, not exploratory memory or scratch files. Replay retains the exact package, output hashes and optional partition assignments. Local replay and platform publication share consumer validation, provenance inheritance and partition algorithms. Local JSONL readers iterate physical lines, preserving embedded Unicode line separators in training text. Publication independently reconstructs step inputs, verifies retained outputs and contamination constraints, and atomically commits the output and partition members. It streams checksum-verified replay files from temporary disk and hashes input records incrementally, without executing the transformation again or materializing all outputs in backend memory. An interrupted publication can resume with its original request key; unknown model acknowledgements still block resume. The task's immutable runtime and workspace generation govern publication.

The backend retains model responses before acknowledging them to the resident runner. A lost acknowledgement with no complete response is marked unknown, never automatically resubmitted. Temporal heartbeats continue during external I/O; coordinator loss reattaches to the resident run. Pause stops new external requests; cancellation revokes publication authority. Complete task results retain primary cells and split members, while dataset preparation retains its own primary cells.

Tasks have no token budget. `max_steps=0` is unlimited; an explicit action limit remains available. Provider usage is reported only when measured. Source quality, semantic assumptions and model performance are not certified by successful execution or format checks.

Conversation checkpoints are copied outside Daytona. Settled task files are retained in Overmind storage before cache eviction and can be restored with exact content and permissions. Total disk loss during an active run can still lose files written since its last retained snapshot; active kernel memory is not archived. Full-population replay and partitioning currently use memory proportional to data size; conversation history remains append-only. New tool observations are bounded structured previews with explicit omissions and a complete local receipt; explicit reads preserve requested pages. Arbitrary agent subprocess cleanup needs additional qualification before production concurrency is increased.

## Verification

Run `scripts/qualify_workshop_resident.py --sandbox ID --report PATH` against a candidate image before enabling live reasoning. It uses scripted model responses, with no LLM calls, to check persistent execution, an exception and repair, runner death during an active kernel call, deduplicated recovery, rejection of undeclared scratch access, clean replay and partitioning.

The [resident trial report](workshop-resident-trial.md) records live release identities, failures, fixes and independent Titanic output audits. The [architecture proposal](../NATIVE_AGENT_ARCHITECTURE_PROPOSAL.md) records the implemented boundary and remaining scaling limits.

## Context preparation

Local Agent Skills for decision and conversation data load with the first relevant exploration call. They carry canonical Overmind consumer contracts, leaving full taxonomy available on demand. No remote skill service or additional model call is required.

A backend-owned dataset briefing measures observed types, nulls, blanks and exact duplicates, with bounded examples. It is bound to project, dataset, cell, source hash, runtime and profiler version; corrupted caches are recomputed and changed source bytes are rejected. The staged briefing is read-only. These are measured structural facts, not inferred targets or a semantic quality certificate. `workshop_runtime.data.stage` produces the same input projection as clean replay, excluding platform-managed metadata; required audit metadata must be retained explicitly in the package.

Native execution guidance requires precomputed source/group lookups and pairwise masks, bounded comparisons for large data, and consistent explicit numeric boundary conventions. Independent full-population verification remains required where feasible; these optimizations do not substitute shared transformation code or sampled assertions. Computed audit reports use the installed JSON-value converter for NumPy and missing-value semantics.

The conversation skill distinguishes the installed column-type checker from full chat validation. The full shared chat validator executes in platform publication before output acceptance; it is not importable in the minimal Daytona image. Agents independently verify message contents, roles and tool pairing locally and must repair rejected publications. They do not search for unavailable training readers or claim local structural checks are full consumer validation.

## Workspace retention and cache

Overmind storage is authoritative for sources, published outputs and retained settled-task snapshots. The existing native worker performs idle-project maintenance every 30 seconds. It stores full task inventories and SHA-256-verified compressed chunks, deduplicated within each project, and commits the manifest on `WorkshopTask.retention` before eviction. Small files transfer in batches; larger files transfer in 32 MiB chunks so retention needs no second full workspace archive.

`WORKSHOP_CACHE_BYTES` defaults to 2 GiB per project for retained inactive copies. Least recently accessed copies are evicted first. Low-disk cleanup can evict verified cold copies earlier, targeting free space of the smaller of 1 GiB or 10% of disk capacity. Running, paused, uncertain and unretained work stays pinned outside that budget. Clarification-blocked tasks qualify only after a successful finish and settled requests. Unknown directories are not deleted. The limit is therefore not a hard cap on all sandbox disk usage; unresolved work needs reconciliation.

Eviction rechecks platform bytes, task state, project ownership, workspace generation and the current local inventory. Failed verification leaves local files intact. Recovery checks free space, downloads verified chunks into a sibling staging directory, restores file permissions and internal links, checks the full inventory and atomically installs it. Interrupted installs can retry without exposing partial input. A retained-task supervisor restores its files before reattaching. Maintenance yields between transfer batches if a new task claims the workspace; no archival transfer is added to the model loop.

Platform storage and database manifests must be backed up together. Retention errors are logged by `workshop-agent`; deleting the only copy is never used to meet the cache budget. This does not snapshot live Python memory or guarantee recovery of uncheckpointed active changes after total sandbox loss.
