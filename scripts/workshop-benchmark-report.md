# Native Workshop ten-dataset benchmark

This benchmark starts each case with original public observations and a short natural intent. Source downloads, deterministic selections, task IDs, attempts, packages, outputs and audit results are retained under `output/workshop-benchmark/`. The native agent receives no benchmark validator or task-specific transformation code. It runs in the persistent Daytona environment. Operator tools use the local Overmind MCP and CLI; the native agent does not.

A pass requires a published artifact, retained executable recipe, independently checked source meaning and values, compatible consumer structure, justified exclusions, leakage checks and appropriate partition relationships. Model training is not part of this benchmark; data preparation quality is distinct from predictive performance. Failures remain recorded and cases are not replaced to improve the score.

## Source provenance

Public sources are [Palmer penguins](https://github.com/allisonhorst/palmerpenguins), [UCI Wine Quality](https://archive.ics.uci.edu/dataset/186/wine+quality), [UCI Dry Bean](https://archive.ics.uci.edu/dataset/602/dry+bean+dataset), [UCI SMS Spam Collection](https://archive.ics.uci.edu/dataset/228/sms+spam+collection), [UCI Bike Sharing](https://archive.ics.uci.edu/dataset/275/bike+sharing+dataset), [UCI Online Retail](https://archive.ics.uci.edu/dataset/352/online+retail), [SQuAD](https://rajpurkar.github.io/SQuAD-explorer/), [Dolly](https://huggingface.co/datasets/databricks/databricks-dolly-15k), [Anthropic HH-RLHF](https://huggingface.co/datasets/Anthropic/hh-rlhf) and [HateXplain](https://github.com/hate-alert/HateXplain). HH-RLHF is used for preferences, not supervised dialogue training.

## Results

Nine cases pass the requested data-preparation objective. Retail produces a valid, explicitly limited historical proxy; the source cannot establish first-ever completed orders, so this is not ten unqualified passes. All ten final recipes pass source-value, consumer-contract, lineage, partition and clean-replay checks for their documented output semantics. They publish 47,173 training/evaluation rows, with excluded observations retained separately for audit.

Including the rejected first preference attempt (17 turns, 334,429 tokens), the eleven agent runs consumed **2,867,839 reported tokens across 159 resident turns**. Usage is measured provider usage, not an estimate or a cap. Preparation succeeds on these bounded cases, but its token efficiency still needs work.

All ten independent replays reproduced every step's output hash and the exact partition assignment hash on the corrected runtime with zero model calls. The nine original packages changed only their runtime pins; the final preference package replayed unchanged. These results establish preparation correctness against the checks above, not trained-model accuracy.

Concrete output checks include:

- Bikes: the training dates end on 2012-05-31, development covers June–August 2012, and final covers September–December 2012. Every target is independently recomputed from `cnt >= 100`; actual same-hour weather and rental counts are absent from inputs.
- Retail: all 500 customer histories are retained in an audit cell. The 471 eligible targets contain 111 observed repeat purchasers and 360 negatives with complete 30-day observation windows. Excluded customers have no invented labels. Invoice records cannot establish verified completion or lifetime purchase history; rerunning the model cannot supply that missing evidence.
- Preferences: all 500 original pairs remain verbatim in a lineage-bound audit cell. The one comparison with identical continuations has an explicit quarantine reason and no decision label. The 499 active rows have 247 preferred-A and 252 preferred-B outcomes; the valid blank continuation is retained. Full conversation/continuation boundaries and original preference direction were checked row by row.
- Annotator judgments: all three votes per post contribute to the target distribution. The 487 disagreement cases retain those fractions instead of being collapsed into a majority label.

Machine-readable results are in [summary.json](../output/workshop-benchmark/summary.json), with per-case audit and replay paths and direct local dataset links. Original failed attempts and their packages remain available alongside final results.

## Failures and general changes

- Penguins initially used nonexistent `source_row`/`split` assignment fields. The agent inspected the error and corrected its verification to use positional `row`/`role`. The staged native contract now documents the assignment wire format and source-identity distinction, plus the explicit holdout-rule shape.
- Wine initially used an invalid `json` column type, then assumed one source column had a uniform landed type. Replay rejected both errors. The agent repaired its schema, retained explicit numeric parsing and repaired an independent-check type error before publication.
- The original Dry Bean XLSX was rejected before agent execution because the source service did not accept spreadsheets. Streaming workbook landing now preserves sheet/row identity and nonliteral cell types, keeps formulas unevaluated and original bytes retained, and rejects ambiguous headers. The unchanged workbook landed successfully. The case was not substituted or flattened by the operator. File/store checks (35), upload/catalogue checks (51), frontend typecheck and the Data Workshop journey passed.
- The bean agent initially passed an extensionless retained-original path directly to `openpyxl`. It read the error and opened the same bytes as a binary stream instead. No package installation was needed. Original filenames are available in `input.json`; preserving them in staged paths remains a usability improvement to consider.
- During the local capacity test, a transient database-connect timeout interrupted the benchmark observer. The task continued under its existing identity. Read-only observation now retries transient connection/5xx failures; mutation retries continue to use stable request keys.

Retail exposed a chained-step representation mismatch: two excluded-customer rows omitted optional keys during replay, while table publication filled those keys with nulls. The agent recovered by retaining the all-customer audit as a parallel branch and deriving decisions directly from source. Shared table-row normalization now gives sequential transformations the same input representation. A related source-reader regression demonstrated rounding of nullable large integers; the Arrow-backed reader preserves exact integers and decoded JSON scalars. Both regressions failed before the fix and pass in focused checks and live LLM-free qualification. The new runtime also passed deliberate runner interruption, exactly-once mutation recovery, isolation and two-step partition checks. Retail also explicitly refuses to claim verified first-ever/completed-order ground truth or future-cohort performance from invoice records alone.

The first preference trial preserved a directional label for one identical-candidate pair. The independent audit rejected that comparison as non-identifiable supervision. The shared taxonomy now separates source retention from active training eligibility: retain such observations in an audit output and quarantine them without inventing tie probabilities. The fresh retry used the same 500 original pairs and unchanged intent, completed without execution errors, and passed independent source/quarantine/split checks and clean replay. The agent correctly retained 499 active comparisons and all 500 audit records; no dataset-specific rule was added to its instructions.

The independent SMS auditor initially parsed raw numeric-looking and quoted messages as JSON. The published text already matched the source exactly; correcting the auditor’s representation handling resolved the false failures without changing or rerunning the agent.

Initial trials used runtime `sha256:cceee1595c7f5ab48fb4b3821c008984a302309864358ab8a86d1293c7fe18f5`. The corrected, bound runtime is `sha256:9ef0b54c87114a515d9ab905d01ba6dd55388537a2b888744342cf8c630f7f18`; all nine accepted packages reproduced every step and assignment hash there with no model calls, after changing only their runtime pins. The completed preference retry used the corrected runtime and updated shared supervision reference, and its unchanged package also passed independent replay. The OpenRouter model route is `openai/gpt-6.1-sol`. Trials share one project workspace and execute sequentially. Independent audits compare published rows to original source bytes and source lineage; replay uses the retained package in Daytona, not host execution of model-authored code.

The required load suite passed its dataset-scale, streaming-connection and read-load checks. Its mixed-workload wrapper first lacked `SANDBOX_TEST_IMAGE`. With the rebuilt local image supplied, six child checks passed, but the mixed soak failed `No shared window with training and every competing workload` (`tests/journeys/.runs/20261107T035158Z/mixed-capacity.log`). ## Remaining limits

This is a bounded preparation benchmark, not proof that arbitrary data or intent is solved. No model was trained or scored, no model-specific context-length/truncation qualification was performed for the dialogue outputs, and pretraining contamination is unknown. Retail needs completion-status records and sufficient customer history to satisfy its literal objective; its current proxy must remain labeled as such.

The workspace still admits one writer per project. The largest supplied case contains 40,361 transaction lines; in-memory frames and pairwise similarity work have not been qualified for much larger inputs. Repeated model context contributes substantially to usage. Runner interruption and checkpoint migration were verified; automatic recovery after total workspace disk loss was not. The separate mixed-workload capacity test remains failing as documented above.

Found but not changed: retained original files use hash-only paths (the bean run recovered by opening a binary handle), and task progress currently mixes action sequence and resident-turn counters. The table therefore uses final `resident_turns`, not the fluctuating live `step` field.
